## 1. Thiết kế

Người làm: Claude Opus 5.5, phiên tự hành. Skill `build-agent-workflow`. Không gọi Gemini thật; mọi test dùng LLM giả hoặc client giả.

**Schema** (`@studio/contracts`, `research/schema.ts`)
- `researchSchema`: `schemaVersion: 1`, `summary`, `facts[]` (`statement`, `claimStatus`, `sourceIds` 1–5), `sources[]` (`id`, `title`, `origin`, `url` http/https). Fact không có source bị từ chối. Source `fetched_url` phải có `url`; source id không được trùng.
- `fetchLogSchema`: `requests[]` gồm `url`, `finalUrl`, `status`, `contentHash`, cộng `error` tùy chọn để ghi dòng lỗi.
- `filterResearchFacts`: chặn ở code, không dựa vào model.
  - Fact trỏ tới source id không tồn tại bị loại (`unknown_source`).
  - Fact `verified` bị loại (`unverified_source`) khi một source của nó không chứng minh được nguồn. Source `fetched_url` phải khớp `url` hoặc `finalUrl` của một dòng fetch 2xx có hash. Source `user_reference` phải thuộc reference của project.

**Fetch** (`apps/worker/src/research/safe-fetch.ts`)
- Chỉ `http`/`https`; URL có user:pass bị từ chối.
- Host của mọi hop phải nằm trong allowlist: host của các URL Director đưa cho project.
- Mỗi hop resolve DNS một lần. Có một địa chỉ bị chặn là chặn cả host.
- Socket nối đúng địa chỉ vừa kiểm qua `lookup` ghim sẵn, không resolve lại, chống DNS rebinding.
- Dải bị chặn:
  - IPv4: private, loopback, link-local, gồm metadata 169.254.169.254; CGNAT, gồm 100.100.100.200; 0/8, multicast, reserved, các dải TEST-NET.
  - IPv6: `::`, `::1`, mọi IPv4-mapped, NAT64, ULA (gồm `fd00:ec2::254`), link-local, site-local, multicast.
- Tối đa 3 redirect, 15 giây tổng, 1 MB (theo `content-length` và trong lúc đọc).
- Content-type chỉ nhận `text/html`, `text/plain`, `text/markdown`, `application/xhtml+xml`.
- HTML được trích thành văn bản thô: bỏ script/style; tối đa 20 000 ký tự mỗi trang.
- Lỗi nào cũng ra một dòng `fetch_log` có `error`, không ném lỗi ra ngoài.

**LLM** (`llm/research-prompt.ts`, `llm/gemini-research-adapter.ts`)
- Interface `ResearchLlm.extractResearch`.
- Model chỉ trả `{ summary, facts }`. `sources[]` do code dựng từ tài liệu đã đọc/fetch; model chỉ được trích id do code đặt (`ref-n`, `url-n`).
- Tài liệu nằm trong khối `<untrusted_documents>` dạng JSON, `<` được escape nên nội dung không đóng được khối. System prompt yêu cầu không làm theo chỉ dẫn trong tài liệu.
- Adapter Gemini dùng `generateWithSchemaRepair` (một lần repair).
- Không Search grounding, không tool: request chỉ có `systemInstruction`, `userPrompt`, `responseJsonSchema`, `model`, `thinkingLevel`.
- Model research dùng chung `GEMINI_MODEL_SCRIPT` / `GEMINI_THINKING_LEVEL_SCRIPT`, không tự điền model ID mới (AGENTS.md).

**Job** (`research/research-job.ts`)
- `runResearchJob(db, jobId, deps)` chỉ nhận `jobId`.
  1. Job đã `completed`/`cancelled` thì trả `skipped` và không gọi provider (idempotency).
  2. `claimJob`: job `running`, `attempt + 1`, agent `running`; run `idea_submitted` → `researching`. Run đã hủy/fail thì `skipped`.
  3. Gom nguồn:
     - file upload md/txt đọc theo key `uploads/<uuid>.<ext>`, chặn symlink/junction ra ngoài `DATA_DIR`; PDF ghi `pdf_not_extracted`;
     - URL fetch qua `safeFetch`.
  4. Gọi LLM.
  5. Validate `researchSchema`, rồi chạy `filterResearchFacts`.
  6. Ghi `artifacts/<runId>/fetch-log-<uuid>.json` và `research-<uuid>.json` (tmp rồi rename, sha256).
  7. `completeJob`: một transaction gồm 2 artifact (version kế tiếp), dependency research → fetch_log, job/agent `completed`, run `researching` → `research_ready`, event.
- Cạnh workflow tính bằng `applyWorkflowCommand` (P3-02). DB chỉ đổi khi status hiện tại đúng `from` (compare-and-set dưới khóa run).
- Lỗi:
  - `schema_invalid` (sau repair), `configuration_missing`, hoặc lỗi provider ở lần thử cuối (`attempt >= max_attempts`): `failJob`, tức job/agent `failed`, run `failed` với `resume_from = researching` và `failure_code`.
  - Lỗi provider ở lần thử chưa cuối: ném ra để BullMQ retry.
- Metadata artifact research: `idempotencyKey`, `jobId`, `rejectedFacts`, `skippedReferences`, `repairCount`.

**DB** (`packages/db/src/agent-jobs.ts`): `loadJobContext`, `claimJob`, `completeJob`, `failJob`, `findArtifactByIdempotencyKey`, `JobStateError`. Mọi event ghi qua `publishEvents` (P3-07).

## 5. Known limitations

- **Chưa có BullMQ Worker consumer.** `runResearchJob` gọi được, nhưng `start-worker.ts` vẫn chỉ reconcile. Gắn processor cho queue `llm` hợp với `P3-04`, khi có route tạo run (`POST /api/projects/:projectId/workflow-runs`, chưa task nào sở hữu). Lý do chưa gắn: gắn consumer thật là gọi Gemini có phí khi có job.
- **PDF chưa trích văn bản**: ghi `skippedReferences: pdf_not_extracted`. Cần thư viện parse PDF, tức dependency mới: Director quyết.
- Trích HTML bằng regex, đủ cho prompt nhưng không phải parser đầy đủ. Chỉ giải mã UTF-8.
- `usage_records` và trần gọi LLM được nối ở `P3-09` (cùng phiên). Sau P3-09, deps của job là `{ client, createLlm?, llmCallCeiling?, dataDir, fetchUrl? }`: job tự bọc client bằng `createMeteredClient`. Test research chạy adapter Gemini thật trên client giả, nên đi qua cả parse, Zod và repair.
- Ghi file xong mà transaction `completeJob` lỗi thì còn file mồ côi trong `artifacts/<runId>/` (không có hàng DB trỏ tới).
- Allowlist là host của URL Director đưa; redirect sang subdomain khác bị chặn. Đó là đúng chữ của 08-SECURITY nhưng có thể chặn trang hợp lệ (ví dụ `example.com` → `www.example.com`), trừ khi Director thêm cả hai URL.
- Gọi Gemini research thật chưa chạy (cần Director duyệt chi phí).
