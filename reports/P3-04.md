## 1. Thiết kế

Người làm: Claude Opus 5.5, phiên tự hành. Skill `build-agent-workflow`.

- **Schema artifact** (`packages/contracts/src/script/schema.ts`): `scriptArtifactSchema` = `{ variants: z.tuple([scriptSchema, scriptSchema]) }.strict()`. Worker và UI P2-07 dùng chung schema này.
- **Research nối sang script** (`research-job.ts`): `completeJob` nhận thêm `nextJob`. Khi research xong, cùng transaction tạo agent `script` cùng job `queued` (queue `llm`, key `script:<runId>:research:<researchJobId>`) và ghi event `agent.status` `queued`. Producer ở MVP là code, không gọi LLM (04-AGENT-ORCHESTRATION).
- **Job script** (`apps/worker/src/script/script-job.ts`), hàm `runScriptJob(db, jobId, deps)`:
  - Bỏ qua khi job đã `completed`/`cancelled`, khi role không phải `script`, hoặc khi run không còn ở `research_ready`/`scripting` (ví dụ đã hủy).
  - Claim job, đổi run `research_ready` → `scripting` khi cần.
  - Đọc artifact research có version lớn nhất của run, validate `researchSchema`, đưa summary và các fact vào prompt. Không có research đọc được thì fail `research_missing`, `resume_from = scripting`, không gọi provider.
  - Nếu key job có dạng `script:<runId>:changes:<approvalId>`: đọc note của approval đó và đưa vào prompt ở khối "Director change request".
  - Gọi `generateScriptVariants` qua `createMeteredClient`: trần `6 + 2 × changes_requested` tính chung cả run, mỗi response ghi một row `usage_records`. Xử lý lỗi giống research: `cost_ceiling`, `schema_invalid` và `configuration_missing` thì fail ngay; lỗi provider thì retry tới `max_attempts`.
  - Ghi file `artifacts/<runId>/script-<uuid>.json` (file tạm rồi rename), rồi `completeJob`:
    - artifact `script`, version tăng theo run;
    - dependency script ← research qua `parentArtifacts` mới;
    - run `scripting` → `waiting_script_approval`;
    - agent `waiting_approval` (`agentStatus` mới).
  - Job không bao giờ ghi `approvals`.
- **Approval** (`packages/db/src/workflow.ts` `recordApproval`), vẫn một transaction như cũ:
  - cổng script + `approved` hoặc `changes_requested`: agent script đang `waiting_approval` → `completed`, kèm event `agent.status`;
  - `changes_requested`: thêm `insertQueuedJob` (agent script + job `queued`, key mang approval id) kèm event `agent.status` `queued`;
  - `rejected`: giữ cổng, agent vẫn `waiting_approval`, không tạo job.
  - Event lỗi thì rollback cả approval lẫn job mới (có test).
- **Redis**: API không kết nối Redis. Job mới nằm ở PostgreSQL `queued`; `reconcileQueues` lúc worker khởi động sẽ enqueue (ADR-003). Consumer chưa gắn (quyết định 5).
- **Helper chung** (`apps/worker/src/jobs/job-support.ts`): `writeJsonArtifact`, `readJsonArtifact`, `isInside` và `advanceTransition` chuyển từ research-job ra đây, hành vi không đổi.
- **Route đọc artifact** (`apps/api/src/routes/artifacts.ts`), `GET /api/artifacts/:artifactId`, response `{ artifact, content }`:
  - artifact JSON: đọc file theo `storage_key`, có realpath nằm trong `DATA_DIR`, giới hạn 2 MB;
  - media (`audio`, `preview`, `export`): `content: null`;
  - không trả `storage_key`;
  - file thiếu hoặc hỏng: 404 `not_found`.
